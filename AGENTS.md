# Repository guidance

Read `README.md` and `openspec/config.yaml` before changing behavior. Use OpenSpec change folders for proposals, delta specs, design and tasks. Keep proposed behavior separate from current behavior. Run `npm run check` for code changes. Do not present text practice as assessed spoken fluency or claim CEFR certification. Protect learner content and avoid sending it to providers without explicit product consent.

## Repository delivery

For this project, when the user asks to implement a change and authorizes delivery, carry it through validation, commit and push to `main`; do not leave completed work only in a local checkout. The user has authorized pushes for this project. If terminal Git cannot authenticate, use the connected GitHub app for the approved repository update, verify the resulting commit on GitHub, then synchronize the local checkout. Do not ask for the same push authorization again. This standing instruction applies to this repository and does not authorize unrelated external changes.
